An interactive public study · language model agents and phylogenetic software

Can a small language model be trusted with a phylogenetic tree?

Five small open language models were given 120 questions about phylogenetic trees, the family-tree diagrams of evolutionary biology, under three conditions: reading the tree unaided, first saying whether they can, and finally operating a real tree library as a tool. This page shows what each condition found, with every answer logged and every number computed from the runs.

Section 1 · What you need to know

Five things, then the study makes sense

  1. A phylogenetic tree shows how a set of species or samples are related: branches join the closest relatives first, the way a family tree joins siblings before cousins.
  2. Trees are written as text in Newick format: nested parentheses. ((A,B),C); means A and B are each other's closest relatives, and C sits outside that pair.
  3. phylo2vec is a published encoding that turns any such tree into a short list of integers and back (Penn, Scheidwasser, Khurana, Duchêne, Donnelly and Bhatt, Systematic Biology, 2025). Its open-source library also measures trees: distances, comparisons, conversions. It is the tool handed to the models in the last act.
  4. The models are five small open language models, one to four billion parameters, each running on a single desktop graphics card: the same five as the DAISY study, where the question was Danish facts instead of trees. For scale, these are hundreds of times smaller than frontier chat models; they are the class that runs cheaply and privately inside a pipeline, which is exactly why their floor is worth measuring.
  5. The question is not whether small models are phylogenetics experts. It is the floor below that: can they read the notation, do they know their own limits, and can they operate the library that does the real work. Those are the abilities an agent inside a bioinformatics pipeline actually needs.

Taxon (plural taxa)
one tip of the tree: a species, strain or sample. Written here as letters A, B, C.
Topology
the branching structure alone, ignoring how the drawing is rotated. ((A,B),C) and (C,(B,A)) are the same topology.
Clade
a branch and everything on it: the smallest group containing two taxa is the group at their meeting point.
phylo2vec vector
the integer list encoding of a tree, one integer per added leaf. Compact, and two trees are identical exactly when their canonical vectors are.
Exact match
the scoring rule: an answer counts only if it is right, letter for letter for words and numbers, same topology for trees. Partial credit does not exist on this page.
Unaided / probe / agent
the conditions: answer alone; first declare yes or no whether you can answer without tools, then answer alone; answer with the phylo2vec toolset, calling tools as often as needed. The agent condition runs twice, differing only in how tool errors are worded.

Act 2 · The honesty probe

Ask it first: can you do this without tools?

This act matters because an agent decides for itself when to reach for a tool. That decision is only as good as the model's self-assessment. Before each unaided answer, every model was asked one extra question: can you determine this reliably by yourself, yes or no. The DAISY study found Mimir claiming to know 382 of the 521 Danish questions it then got wrong; this act runs the same probe on trees.

What you see: for each model, two dots on one 0 to 100 percent scale: how often it said yes, I can do this without tools, and how often its answers were then actually right. How to read it: the horizontal gap between a model's dots is its overconfidence; dots together mean the model knows itself. Take-away: computing…

A model that misjudges itself cannot be left to decide when to use a tool. Act 3 removes the decision: the library is in its hands from the start.

Act 3 · The agent condition

Hand it the library

This act matters because it is the deployable shape: the model is given six phylo2vec-backed tools (count leaves, path length, clade membership, topology comparison, both vector conversions) through a plain text protocol, and may call them as often as it likes before answering. What is measured is not tree knowledge but tool competence: copying a Newick string into a call, reading the result back, knowing when to stop.

The finding, and its measured remedy

The largest single failure in the agent runs was not knowledge: one model kept calling the clade tool with a missing argument, the tool answered with a bare list index out of range, and the model never recovered. That is a harness defect as much as a model defect, so the fix was built and measured: the same runs again, with error messages that name the missing field and show correct usage.

Why this floor matters

What these three findings mean for a real pipeline

Language model agents are starting to appear inside scientific infrastructure, including platforms for pathogen surveillance and outbreak analysis, where they sit next to alignment tools, tree builders and databases. The models that can run at scale inside such a platform, cheaply and on-premise, are precisely the small class measured here. This section says what the three acts imply for building that kind of system.

Act 1 implies the model is never the instrument. A model class that reads a twelve-leaf tree at guessing level must not be the thing that answers questions about a tree; the library computes, the model coordinates. That division of labour has to be enforced by the harness, because, per act 2, the model cannot be trusted to declare its own limits: one model here said yes to almost everything, another said no to almost everything, and both were wrong about themselves. An agent design that asks the model "do you need the tool?" inherits whichever failure its model happens to have.

Act 3 implies the interface is a measurable research object. The same model moved from 54 to 61 percent overall, and from 8 to 36 percent on one task kind, when nothing changed but the wording of an error message. Tool definitions, argument formats and error text are usually written last and never evaluated; this study treats them the way model prompts are treated, as variables with measurable effects, and finds one of the larger effects on the page.

The harness transfers. Nothing in the method is specific to trees: the same generate, verify twice, probe, tool-arm, remedy-arm loop applies to any scientific toolchain a language model agent is asked to operate, an aligner or a lineage-assignment tool as readily as phylo2vec. The companion DAISY study is the same loop on factual lookup; this page is the same loop on structured computation.

What this page gets wrong, stated first

Limits and misses

  • The trees are synthetic and small. Five to twelve leaves, topology only, no branch lengths, no real sequence data. This measures the notation floor, not phylogenetic inference; a real analysis has thousands of taxa and the hard part is building the tree, not reading it.
  • One run, greedy decoding, 120 tasks. No repeats, no confidence intervals. Differences of a few percentage points between models should not be read as rankings.
  • DFM Mimir is out of its domain twice. It is a Danish-language 1B model given English instructions, and it is barely instruction-tuned; its rows are included for continuity with the DAISY study, not as a fair comparison. It is served through the prefix-attention llama.cpp fix from that study.
  • The agent protocol is one design. A plain text protocol with pipe-separated arguments was chosen for robustness across five different chat templates; a native tool-calling format could score differently, in either direction.
  • "Closer" is topological. Path length in branches, stated in every question; on real trees closeness usually means branch length, which does not exist here.
  • The probe changes nothing for the model. Saying no had no cost and brought no tool; a model that always says no loses nothing. The probe measures self-assessment, not strategy.
Coda · How this was built

Method, sources, and how to run it

Tasks. 120 questions in five kinds, generated by a seeded script. Every correct answer is computed twice: by phylo2vec for conversions and topology comparison, and by an independent Newick parser written for this study for paths, clades and counts; the task set ships only after the two agree on every row. Yes/no kinds are balanced.

Runs. Each model is served locally by llama.cpp on one GTX 1060 and queried at temperature 0. Unaided and probe conditions are single turns; the agent condition allows up to five tool rounds and runs twice, once with terse tool errors and once with errors that name the missing field and show usage. Every prompt, answer, claim and tool transcript is logged and shipped in the repository.

Scoring. Exact match. Answers that are trees are compared as topologies, so a correctly rotated Newick counts; everything else is compared as normalised text. Malformed tree answers score zero rather than crashing the scorer.
